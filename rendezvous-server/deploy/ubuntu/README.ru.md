# Ubuntu Server: подготовка закрытой проверки TURN

Этот документ описывает вариант Cloudflare TURN. Для собственного реле на
laptop-server используйте [подготовку coturn](../coturn/README.ru.md): Cloudflare
TURN key, платёжный профиль и его статистика расходов там не требуются.

Эти файлы — шаблоны, а не установленная служба. Реле остаётся выключенным.
Broker встроен в тот же JAR, что и сервер знакомств: отдельный процесс broker
не запускается. Нужны Java 21, nginx и cloudflared. Проверьте версию Ubuntu и
доступность Java 21 перед установкой; не меняйте текущую службу вслепую.

## Существующий сервер и данные

На ноутбуке можно выполнить безопасный обзор без установки и перезапуска:

```sh
bash inspect-server.sh
# Если известно настоящее имя службы:
bash inspect-server.sh peercraft-rendezvous.service
```

Скрипт находится рядом с этой инструкцией; запускайте из её папки либо укажите
его полный путь. Он показывает ОС, Java, наличие nginx/cloudflared, UDP-порты и
несекретные свойства службы. Он не выводит аргументы процессов, переменные
окружения, ключи, аккаунты или журналы сервера. Имя службы в примере замените
на настоящее; путь JAR и фактический `dataDir` ещё нужно проверить отдельно.

Сначала выясните имя текущей службы, путь JAR, UDP-порт и фактическую папку данных.
Если `dataDir` не задан, используется `./data` относительно рабочего каталога.
Сохраните резервную копию всей этой папки при остановленном сервере, включая
`accounts.json`, `handoffs/`, `analytics/` и, если уже есть, `relay-issued.json`.
Не запускайте вторую копию одновременно на том же порту или с той же папкой.

В шаблоне службы указаны `/opt/peercraft/rendezvous-server.jar`,
`/var/lib/peercraft/data`, пользователь `peercraft` и UDP 51000.
Для обновления существующего сервера сохраните его реальные пути, пользователя и
порт либо сначала перенесите полную копию данных. Создание пустой папки вместо
существующей приведёт к отсутствию прежних аккаунтов. `ProtectHome=true` в шаблоне
не разрешает службу с JAR/данными в `/home`: адаптируйте размещение или эту настройку.

Установите собранный `build/libs/rendezvous-server-1.0.0.jar` как JAR службы,
сохранив предыдущий JAR для отката. Дайте пользователю службы право записи только в
папку данных; JAR и настройки службы должны принадлежать администратору.
Изменение службы и запуск на домашнем ноутбуке выполняются отдельно от сборки.

## Ключи на сервере

Создайте `/etc/peercraft`, скопируйте `relay.env.example` в
`/etc/peercraft/relay.env`, установите владельца root и права 0600. Заполните его
редактором непосредственно на сервере. systemd читает EnvironmentFile до смены
пользователя службы. Не вводите секреты в команды, историю терминала, чат или Git.
Формат — `NAME=value`; это не shell-скрипт, команды и подстановки не выполняются.

`CF_ACCOUNT_ID` и `CF_TURN_KEY_ID` — идентификаторы. `CF_TURN_KEY_TOKEN` — секрет
отдельного TURN key PeerCraft. `CF_ANALYTICS_TOKEN` — отдельный секрет с правом
Account Analytics Read на выбранный аккаунт. В мод эти ключи не помещаются.

Скопируйте `relay.properties.example` в существующую папку данных как
`relay.properties`. Сохраните `enabled=false` до этапа закрытой проверки.
`billingStart`/`billingEnd` берутся из подтверждённого периода подписки Cloudflare
в UTC; не подставляйте первый и последний день календарного месяца автоматически.
`exclusiveTurnAccount=true` допустимо только при отсутствии любого SFU в аккаунте.
Если позже появится SFU, нужна настройка общего запроса TURN+SFU из основного README.

Для автоматического получения нового периода укажите `CF_REALTIME_SUBSCRIPTION_ID`
— проверенный ID именно подписки Realtime, и `CF_BILLING_TOKEN` — отдельный токен
с правом Billing Read. Сначала подтвердите доступность API подписки в своём аккаунте.
Новые даты снимают бюджетное отключение только после полной статистики нового
периода. Без этих настроек даты нужно обновлять в конфигурации с перезапуском
каждый расчётный период; иначе реле отключится на его границе.

## Временный HTTPS без домена

Установите cloudflared по [официальным инструкциям Cloudflare](https://pkg.cloudflare.com/).
Установите nginx и поместите `relay-tunnel.nginx.conf` в его `http` context,
например `/etc/nginx/conf.d/peercraft-relay.conf`. Проверьте конфигурацию `nginx -t`
до перезагрузки nginx. Не перезаписывайте его существующие сайты.

Запустите на том же ноутбуке:

```sh
cloudflared tunnel --url http://127.0.0.1:51082
```

Пока идёт проверка, оставьте этот процесс работающим. Из его вывода возьмите
HTTPS-адрес `https://....trycloudflare.com`. Он меняется после нового запуска.
Укажите точный адрес без `/v1/relay` в `advertisedUrl` сервера и в настройке
`relay.brokerUrl` обоих тестовых клиентов. После смены адреса обновите все три.
Не используйте `--allowed-mail`: интерактивный вход через браузер несовместим с API
мода. Защита API — собственные аккаунтные сессии, действительный match и правила
комнаты; знание временного URL не выдаёт credentials.

nginx принимает соединение cloudflared только на loopback, использует
`CF-Connecting-IP` и перезаписывает `X-PeerCraft-Client-IP` перед broker.
Не направляйте tunnel сразу на 51081: broker требует этот заголовок для IP-квоты.
Не открывайте 51081/51082 или панель аналитики 51080 на роутере. Существующий
rendezvous UDP-порт по-прежнему должен быть доступен: tunnel не переносит его.
Cloudflare TURN несёт игровые данные; HTTP tunnel обслуживает только API broker.

Quick Tunnel предназначен для разработки, не имеет гарантии доступности и
ограничен 200 одновременными запросами. Для публичного выпуска нужен постоянный
HTTPS-адрес. [Ограничения Cloudflare](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

## Запуск и проверки

До установки службы адаптируйте шаблон под реальные пути и порт. Сохраните текущую
службу и JAR. Сначала остановите предыдущий процесс, затем примените новую службу
и выполните `systemctl daemon-reload`. Не включайте автоматический запуск до
проверки путей, владельцев, резервной копии и отсутствия второго процесса.

1. При `enabled=false` подтвердите вход/комнаты/прямую игру старого и нового клиента.
2. Подтвердите живой временный HTTPS, ключи, период и доступность полной аналитики.
3. Только на этапе согласованной закрытой проверки установите `enabled=true` и
   перезапустите сервер. До свежей статистики выдача credentials заблокирована.
4. Проверьте прямое подключение без credentials, затем подтверждённый fallback,
   игру, mod-sync на Fabric/NeoForge 1.21.1, передачу/возврат хостинга и продление.
5. Измерьте полный расход Cloudflare за игровые часы и передачу файлов.
6. При ошибке выключите реле и перезапустите; сохраните журнал credentials.
   Не удаляйте `relay-issued.json` для обхода квоты или сброса состояния.

800 GB — запас перед бесплатными 1000 GB всего аккаунта за расчётный период, а не
гарантия нулевого счёта. Аналитика и отзыв credentials имеют задержки. Если полные
данные устарели больше чем на 120 секунд, новые и действующие relay-сеансы
отключаются. Обычные прямые подключения продолжают работать. Не публикуйте
содержимое env-файла и полные ответы с временными credentials при диагностике.
