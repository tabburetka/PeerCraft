# Подготовка собственного TURN на laptop-server

Эти файлы готовятся в проекте. Ничего не установлено на laptop-server.
Основная цель и закрытые проверки: [план](../../../docs/coturn-fallback-plan.md).

## Схема

Игрок → HTTPS broker существующего rendezvous → временные credentials → UDP coturn.
Игра, моды и мир идут через UDP coturn; HTTPS обслуживает только управление.
Для broker можно использовать ранее подготовленный HTTPS reverse proxy/tunnel,
это не требует регистрации в платном Cloudflare Realtime TURN.

Coturn и broker знают один секрет. Клиент получает только временный username/password
и отдельные ключи защищённого PeerCraft канала. На coturn разрешены только peer-IP
его собственного публичного адреса, чтобы выданные credentials не открывали
произвольный UDP-прокси. Это требует проверки двух allocations и NAT hairpin роутера.

## Подготовка файлов (позднее, перед установкой)

Нужны фактический публичный IPv4, LAN IPv4 ноутбука и выбранный HTTPS-адрес broker.
Динамический публичный IP потребует обновления coturn external-ip и broker endpoint;
домен сам по себе не заменяет настройку этого отображения.

```bash
python3 rendezvous-server/deploy/coturn/prepare.py \
  --public-ip PUBLIC_IPV4 \
  --lan-ip 192.168.68.110 \
  --broker-url https://YOUR_BROKER_HOST \
  --output rendezvous-server/deploy/coturn/generated
```

Генератор создаёт новую папку с правами 0700 и три файла 0600, не печатает секрет,
не перезаписывает прежнюю папку и оставляет enabled=false. Не пересылать эти файлы
в чат, не коммитить, не включать в диагностические логи.

## Отдельный этап установки

Для переноса подготовленного JAR и инструкций можно собрать пакет локально:

```bash
mkdir -p rendezvous-server/deploy/coturn/packages
python3 rendezvous-server/deploy/coturn/build_bundle.py \
  --jar rendezvous-server/build/libs/rendezvous-server-1.0.0.jar \
  --output rendezvous-server/deploy/coturn/packages/peercraft-coturn.tar.gz
```

Пакет содержит JAR, генератор, инструкции, план и manifest.json с SHA-256 каждого
файла. Приватные настройки не включаются. Сборщик отвергает JAR без coturn-классов
и существующий output. Это подготовка переноса, а не установщик; manifest не
подтверждает настройки работающего сервера. После изменения кода пересобрать JAR
и создать новый пакет, сохранив предыдущий для сравнения.

1. Снять резервную копию существующей службы и всей папки данных. Проверить реальный
   ExecStart и dataDir; /home/ikuku/peercraft_server — рабочая папка, не доказательство dataDir.
2. Установить coturn из Ubuntu-репозитория. Не заменять rendezvous другим экземпляром.
3. Приватно установить turnserver.conf и relay.env. Coturn должен читать секрет как
   свой пользователь службы, broker — через EnvironmentFile существующей службы.
   Права конфигурации coturn: root:<фактическая группа coturn>, 0640; env: root, 0600.
   Сначала сверить unit пакета Ubuntu; не угадывать путь или пользователя.
4. Обновить JAR существующего rendezvous и relay.properties в его фактическом dataDir,
   сохранив аккаунты, handoff-журналы, пользователя службы и UDP 51000.
5. На роутере закрепить Wi-Fi .110 и пробросить UDP 3478, 52000–52031 на .110.
   Установить соответствующие правила firewall. TCP TURN пока не используется.
   Порты broker 51081/51082 не открывать в Интернет напрямую.
6. Подготовить доверенный HTTPS broker и указать его URL на сервере и двух клиентах.
7. После проверки конфигураций включить только для закрытой проверки, подтвердить
   двусторонний TURN из внешних сетей, работу игры/mod-sync/handoff и нагрузку.

Начальный broker лимит: 2 соединения. В coturn 8 allocations, по одной на username
(две стороны × старая/новая allocation × два соединения), max-bps=1 MiB/s на allocation,
bps-capacity=8 MiB/s для резерва ротации. Это не измеренная пропускная способность
ноутбука и не гарантированный лимит физического интернет-канала. При достижении
max-bps coturn подавляет/теряет пакеты: до выпуска измерить задержки и уменьшить
скорость прикладных передач при необходимости. Broker уже задаёт 512 KiB/s для
файловых протоколов, чтобы оставался запас для игры и транспортных обёрток. При переходе к 4
соединениям пересмотреть coturn квоты и только после нагрузочных проверок.

## Отключение и восстановление

enabled=false с перезапуском broker запрещает выдачу и закрывает штатные каналы.
Выданные coturn REST credentials нельзя индивидуально отозвать. Они остаются
применимыми до своего срока, а уже созданная allocation изменённого клиента
может жить дольше; TTL credentials не равен принудительному прекращению данных.
Для аварийного полного выключения требуется остановить coturn.

После перезапуска broker outstanding credentials сохраняются в relay-issued.json;
новый допуск ждёт их истечения до 15 минут. Журнал не удалять для обхода ожидания.
Смена провайдера также учитывает старые выданные credentials: прежде надо закрыть
старый TURN сервис/доступы и дождаться их срока, а не считать их coturn credentials.
После замены секрета синхронно обновить обе службы в отдельном окне обслуживания.

## Локальные проверки

```bash
python3 -m unittest discover -s rendezvous-server/deploy/coturn -p 'test_*.py'
cd rendezvous-server
./gradlew test jar
```

Синтетические проверки не подтверждают публичный проброс, HTTPS или качество игры.
Настоящий локальный coturn проверяем отдельно и затем повторяем на ноутбуке.

Для повторяемой локальной проверки установленный или распакованный доверенный
coturn передаётся через PEERCRAFT_TEST_COTURN_BIN. Бинарник сам запускается тестом
только на 127.0.0.1, с отдельной временной конфигурацией и завершается после теста.
allow-loopback-peers используется только в тестовой конфигурации, не в подготовке
публичного сервера. Если бинарнику нужны распакованные библиотеки, задайте
LD_LIBRARY_PATH только для этой команды. Подпись пакета проверяйте до запуска.

```bash
cd peercraft
PEERCRAFT_TEST_COTURN_BIN=/absolute/path/to/turnserver ./gradlew \
  :1.21.1-fabric:test \
  --tests '*CoturnIntegrationTest' \
  --tests '*RelayModSyncIntegrationTest' \
  --tests '*RelayWorldTransferIntegrationTest' \
  --tests '*BulkPacerTest' \
  --tests '*PeerRouteIntegrationTest' \
  --tests '*HandoffLoopbackIntegrationTest'
```

Без этой переменной настоящие coturn-тесты явно пропускаются; синтетические
продолжают работать. Успешная обычная сборка не считается coturn-проверкой.
