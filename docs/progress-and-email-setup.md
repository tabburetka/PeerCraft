# PeerCraft: прогресс игроков и восстановление аккаунта

Рабочая ветка: `experiment`. Изменения не требуют пересоздания аккаунтов или миров.
Не удаляйте базу аккаунтов сервера: именно её UUID связывают аккаунты с сохранениями.

## Старые гостевые сохранения

Новые подключения через PeerCraft требуют входа в аккаунт. Регистрация создаёт новый
UUID аккаунта; старое гостевое сохранение остаётся в мире хозяина. Оно не присваивается
по нику автоматически.

1. Игрок регистрируется и сообщает хозяину свой код друга.
2. Хозяин сохраняет и закрывает мир, входит в PeerCraft и открывает
   **Аккаунт → Прогресс игроков → Привязать старый прогресс**.
3. Хозяин выбирает мир и старый UUID. Опыт и список вещей помогают узнать сохранение;
   выбор нужно подтвердить с самим игроком.
4. Код друга проверяется на сервере аккаунтов. В подтверждении показаны старый UUID,
   аккаунт и его UUID. После подтверждения создаётся проверенная копия мира в
   `<мир>/.peercraft-backup/progress-<случайный UUID>.zip` и выполняется перенос.
5. Игрок подключается с тем же аккаунтом. Повторная регистрация для восстановления
   не нужна: она создаст другое удостоверение игрока.

Исходные файлы остаются. Перенос включает данные игрока, статистику, достижения и
ссылки владения питомцами; `Data.Player` сохраняется для совместимости с Minecraft.
Если у получателя уже есть данные в этом мире, операция останавливается. Слияния
инвентарей или перезаписи существующего прогресса нет. Привязанные UUID нельзя
передать другому аккаунту этой операцией.

Для отката закройте Minecraft, сохраните текущий каталог мира отдельно и распакуйте
нужный ZIP **в новый каталог**, затем откройте восстановленную копию. Не распаковывайте
копию поверх мира: там могут остаться файлы после переноса. Резервные копии и журнал
миграции остаются у хозяина и не передаются архивом handoff. Метаданные идентичности
передаются вместе с миром. Прямой LAN пока использует ванильные UUID; переход LAN ↔
PeerCraft требует отдельной проверки и явного выбора старого сохранения.

## Настройка почты на сервере

1. Скопируйте `rendezvous-server/deploy/email.properties.example` в `data/email.properties`
   внутри каталога данных действующего сервера. Укажите SMTP-хост, порт и адрес отправителя.
2. Передайте `PEERCRAFT_SMTP_USER` и `PEERCRAFT_SMTP_PASSWORD` окружением службы сервера.
   Пароли не кладутся в файл настроек или клиентский мод.
3. Для порта 587 оставьте `smtp.implicitTls=false`: STARTTLS обязателен. Для SMTP с
   непосредственным TLS (обычно 465) включите `smtp.implicitTls=true`.
4. Настройте HTTPS-домен. Пример nginx находится в `deploy/email.nginx.conf.example`:
   обработчик слушает только `127.0.0.1:51082`, прокси обязан перезаписывать
   `X-PeerCraft-Client-IP`. Альтернатива — PKCS12 в `https.keyStore` и его пароль через
   `PEERCRAFT_EMAIL_KEYSTORE_PASSWORD`; тогда HTTPS обслуживает сам сервер.
5. Поставьте `enabled=true`, сохраните резервную копию базы аккаунтов и перезапустите
   сервер. Используйте действующие данные аккаунтов, а не новый пустой каталог.
6. На клиенте укажите полный endpoint, например
   `-Dpeercraft.email.serviceUrl=https://accounts.example.org/v1/account/email`
   или `PEERCRAFT_EMAIL_SERVICE_URL`. Для распространяемых сборок адрес можно положить
   в `peercraft-defaults.properties` как `email.serviceUrl`. Адреса примеров нужно заменить.

Провайдер должен разрешать выбранный адрес отправителя. DNS и доставка на реальные
почтовые ящики проверяются после настройки провайдера; локальные тесты их не заменяют.
Для рабочей эксплуатации сохраняйте независимые резервные копии базы аккаунтов.
При повреждении существующей базы сервер откажется стартовать и оставит файл для
восстановления; он не начинает автоматически с пустого списка аккаунтов.

## Действия игрока

Для нелицензионного аккаунта: **Аккаунт → Прогресс игроков → Привязать почту**.
Нужны действующая сессия, текущий пароль и код из письма. Новая почта вступает в силу
только после подтверждения; прежняя получает уведомление о смене.

Если пароль забыт: на экране аккаунта нажать **Восстановить аккаунт**, указать ранее
подтверждённую почту, ввести код и новый пароль дважды. Восстанавливается прежний UUID
и код друга. Старые сессии, сохранённый вход и начатые проверки старого пароля отзываются.
После восстановления нужно войти заново; публичная карточка с UUID сохраняется локально.

Код действует 15 минут, однократно, с ограничением попыток. Ответ на запрос письма
не раскрывает, зарегистрирован ли адрес. Письма обрабатывает ограниченная очередь;
при сбое доставки можно повторить запрос после ограничения частоты.
