# Версии Minecraft в мониторинге — 19.10.2026

## Причина по рабочему серверу

Прочитан LAN API `http://192.168.68.110:51080/api/analytics`.
В снимке `2026-10-19T17:37:49.460Z`:

- `unknown`: 359 регистраций.
- `room.private`: 179; `room.friends_only`: 180. Сумма ровно 359.
- `room.public`: 850. Сумма известных версий тоже 850.

В существующем REGISTER версия сериализовалась только при `publicRoom=true`.
Сервер учитывал версию каждой новой комнаты, превращая пустое значение в `unknown`.

## Исправление

Современный и Java 8 кодеки передают версию непубличной комнаты в необязательном
трейлере `0xCB`, версия схемы 1, после существующего connectivity.
Изменены все три варианта RendezvousClient. Публичные пакеты сохранены побайтово;
название приватного мира не отправляется и комната не попадает в публичный список.
Старые серверы игнорируют трейлер. Для учёта нужны обновлённые клиент и сервер.

Панель показывает только переданные версии в рейтинге, а число регистраций без
версии и покрытие — отдельно, на русском и английском. Старые агрегаты сохранены.
Точный номер версии у прежних записей без версии восстановить нельзя.
`AnalyticsStore` сохраняет `unknown` отдельно от `other` и после лимита разных версий.

## Подготовка установки

На момент подготовки служба `rendezvous.service` активна, рабочий JAR ещё не заменён.
Проверено по SSH: пользователь `ikuku`, каталог `/home/ikuku/peercraft_server`.
Перезапуск требует пароль sudo. Обновление загружено отдельно в
`/home/ikuku/peercraft_server/updates/analytics-version-20261019/`.
Контрольная сумма загруженного JAR проверена:

```text
f8054b2b745f2bb4742a2bb68763f596290e2406ae43cad3cee9613ff4ae24e9
```

На ноутбуке сервера выполнить:

```bash
bash /home/ikuku/peercraft_server/updates/analytics-version-20261019/install.sh
```

Установщик проверяет прежний и новый JAR, запрашивает sudo до остановки, сохраняет
копию JAR, unit и архива всей data после остановки, атомарно заменяет JAR и проверяет
службу/HTTP. При ошибке возвращает прежний JAR и запускает службу. Остановка сбросит
текущие записи комнат в памяти; активные хосты зарегистрируют их повторно.

Расширенная клиентская телеметрия остаётся предложением:
[план следующего релиза](../telemetry-next-release.md).
